# AgentVibe的东西 真的看懂了吗

Agent时代，开发个人程序前所未有的简单。归功于足够强的模型，一个想法，几句提示词，一个项目往往就能跑起来。

页面能开，接口能通，README 写得工工整整，启动起来像个正经产品。那会儿我真心觉得，自己在变强，我去，我怎么这么牛逼。

直到有人问我一句：这些代码，合上电脑，你还能讲清几个"为什么"？

我卡住了。

功能当然讲得出。但"为什么要开这个事务""为什么这个状态机这么设计""为什么 WebSocket 堆积的时候先丢最旧的那条"——我答不上来。代码能跑，只是因为AI提前踩完了所有的坑，至于为什么选择这套架构，那些事还是见上帝去吧。

更麻烦的是，即使开了好几个 agent，一个写代码，一个查资料，自己坐在中间，运筹帷幄，是不是有点包工头的感觉了。可那些代码要是经不起"为什么"，我拿到的就只是一个看起来很能干的幻觉。

缓存一致性、幂等、事务边界、部署回滚——碰到这类真麻烦，我的第一反应不是啃，是"换个简单的，做个新 demo 吧"。新 demo 多干净，不碰脏数据，不碰并发，跑起来还好看。于是项目越来越多，每个都光鲜，但是能力呢，似乎没怎么增长。这跟买一摞书，最后发现书皮都没拆。但是人总能自我安慰：我确实在写啊，我确实在忙啊。

这导致了一个问题，一直被AI牵着鼻子走，没有自己的想法，也形成不了自己的思维体系。

怎么办呢，解铃还得系铃人，问AI吧——

得到了三个结论，在这分享一下:

一，收敛。同时只留一个主项目、一个兴趣项目，其余冻结。新想法只记一句话，不急着开仓库。

二，每周啃一个不知道答案的问题。不要求一定解决，只要求对它的认知比周一更可靠。哪怕结论是"我排除了 A 和 B，问题出在客户端消费和服务端队列之间，方案还没定"，这一周也值。

三，agent 可以写代码，但我必须能接管。它写完，我自己走一遍，改一个条件，看它还对不对。做不到，就不算学会。

是不是很讽刺——一个靠 AI 的人，反而最提防 AI。但道理我后来想通了：我不是要证明不用 AI 也能写，我是要证明，无论代码谁写的，我都能理解需求、判断方案、分析风险、最终验收。

那天下午面试，面试官没问技术栈，也没问八股。他问我：普通人拿到这个 agent，能直接做开发吗？

我说能降低门槛，但做不好开发。真正的瓶颈从来不是会不会敲代码，而是知不知道自己在做什么。

使用AI，理解AI，尝试驯服AI——VibeCoding这一个月，我得出这样一个结论。
